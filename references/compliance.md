# 合规与边界

本项目处理的是**求职者个人信息**，属于《个人信息保护法》下的敏感场景。使用前请逐条确认。

## 一、能做 / 不能做

| 能做 | 不能做 |
|---|---|
| 在你本人的企业账号下查看系统本来就会展示给你的候选人 | 用他人账号、共享账号、或批量注册账号 |
| 把候选人名单整理成表格，用于自己的招聘跟进 | 把简历数据转卖、公开、发到群里、上传到公开仓库 |
| 对候选人做内部分析（画像、漏斗、岗位匹配） | 对候选人做与招聘无关的画像或推断 |
| 逐个打开简历、记录沟通要点 | 高频批量抓取全站简历 |
| 手动决定联系谁 | 批量群发、自动打招呼刷量 |

代码层已硬拦截第二列中的「批量群发 / 绕验证码 / 代登录 / 破解签名」，改代码之前请先想清楚后果。

## 二、个人信息处理

1. **最小必要**：只取招聘评估需要的字段。默认掩码手机号、邮箱、姓名（`138****1234` / `zh***@example.com`）。
2. **明文的门槛**：`--no-mask` 是显式动作，意味着你确认本地存储环境可控。
3. **留存期限**：建议 30 天内清理未被推进的候选人数据；`data/` 目录不入库、不上云盘同步。
4. **不得二次利用**：候选人数据不得用于营销、不得提供给第三方、不得用于训练模型。
5. **删除义务**：候选人要求删除时，删掉 `data/raw/resumes.jsonl` 与 `data/clean/*.csv` 中的对应记录。

## 三、平台规则

- 遵守 BOSS 直聘用户协议与机器人条款。本项目定位是**辅助你已有的招聘工作**，不是替代人工的采集器。
- 不绕过任何人机校验。遇到 `code=37`、滑块、点选验证，一律停机交人工。
- 频控默认 3–7 秒随机间隔、单次 ≤50 位候选人、单日有预算上限。这些不是性能参数，是保护措施，**不建议调高**。
- 账号风险自负：自动化操作可能触发风控导致账号受限。若被限制，停止使用并走官方申诉，不要尝试绕过。

## 四、技术边界

| 不做 | 原因 |
|---|---|
| 逆向 `__zp_stoken__` 生成算法 | 属破解，且 JS 每日变化，维护成本不可持续 |
| 用无头浏览器伪装真人 | 指纹差异明显，误伤账号 |
| 代理池 / IP 轮换 | 属规避风控 |
| 接入第三方打码平台 | 违反平台规则，且涉及个人信息外流 |
| 保存账号密码 | 无必要，复用浏览器会话即可 |
