Agent Skill · 方案说明

boss-recruiter-skill

以企业招聘者身份驱动本机真实 Chrome，复用已登录会话，把「在招职位 / 候选人 / 简历」变成本地结构化数据。不逆向加密、不代理登录、不绕过验证码。

playwright-core 驱动 Chrome 页面内响应捕获 jsonl → csv → stats 10 / 10 测试通过

一、技术路线为什么这么选

BOSS 的风控是组合拳：动态 __zp_stoken__、设备指纹校验、极验 + 易盾、前端反调试。三种方案的实际结果差别很大。

路线 A
纯 HTTP + 逆向签名
  • 安全 JS 每天换版本
  • 算法依赖 Canvas/WebGL 指纹
  • 维护成本极高，且属破解
路线 B
无头浏览器硬爬
  • 无头环境指纹与真人差异明显
  • token 对了也可能被拒
  • 容易误伤账号
本项目
真人浏览器 + 复用会话
  • 签名由浏览器自己算
  • 指纹就是你日常的本机环境
  • 接口改版不影响主流程

二、数据流

01
持久化会话
独立 profile 目录，扫码一次长期复用
→
02
响应捕获
监听所有 JSON 响应，不依赖接口路径
→
03
字段归一化
按字段特征识别候选人 / 简历 / 职位
→
04
主键合并
encryptGeekId 去重，保留首末次出现
→
05
落地输出
jsonl 快照 / CSV / stats.json

两个关键设计

1. 不硬编码接口。捕获器监听 context 上所有 application/json 响应，抽取器用字段特征判断「这是什么数据」。接口改名、加参数、换版本，主流程照跑。想提速再用 boss probe 抓到的确切路径填进配置走直连。

2. 抓不到就退回 DOM。简历详情若拿不到 JSON，自动退回可见文本抽取，保证不空手而归 —— 两条兜底路径，而不是赌单一接口。

五、边界写在代码里

文档里的提醒容易被忽略，所以关键约束做成了能抛错的逻辑：

  • ✕批量群发、自动打招呼 —— PolicyError 直接拒绝
  • ✕绕过验证码 / 逆向签名 / 代登录 —— 关键词命中即拦截
  • ✕单日预算超限 —— 跨进程累计，超出报错而非静默降级
  • ✓个人信息默认掩码：138****1234 / zh***@example.com
  • ✓风控命中（code=37、环境异常）立即停机，交人工处理
  • ✓每次操作写 data/audit.log，可回溯

实现过程中踩到一个坑：puppeteer-core 最新版仍与本机 Chrome 157 的 CDP 协议不兼容（Requesting main frame too early），所有启动方式均失败；改用 playwright-core + channel:'chrome' 后一次通过。

七、开始使用

# 安装
npm install && npm link
boss doctor

# 登录（弹出真实 Chrome，扫码后会话长期复用）
boss login

# 先小批量验证链路
boss candidates --limit 20
boss stats

# 稳定后再按需加量
boss candidates --job <jobId> --limit 50
boss resume --url "<候选人详情页>"
boss export --what candidates
→ data/clean/candidates.csv

八、使用前提

这套工具处理的是求职者个人信息，只在以下前提下使用：

  • ✓你本人拥有已认证的企业招聘账号
  • ✓数据仅用于你的招聘评估，不转卖、不公开、不入公开仓库
  • ✓控制留存期（建议 30 天内清理未推进的候选人数据）
  • ✕不具备企业账号、或用途涉及批量采集转售 —— 请勿使用
